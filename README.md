## 日常使用（最小维护流程）

1. 新课后：仅在相应 `notes/` 追加值得留下的概念、条件或反例，必要时更新 `progress.md`。
2. 独立做题后：只有代表性解题才加入 `practice/`；记录题意、实际作答、是否提示、关键验证，不为每道简单题新建文件。
3. 做错后：在 `mistakes/mistake-log.md` 保留**原错误 → 发生原因 → 修正 → 下次复测**。
4. 每次复习：优先打开 `reviews/review-queue.md`，先闭卷回答，再看笔记核对；“看懂答案”不算独立通过。
5. 复习完成：简短更新复习队列和当前进度；使用 Git 提交历史保留变更，不重复复制全文。

建议节奏：新知识当天做少量题，约 3 天和 7 天后各快速复测一次；若连续正确且能解释条件，再降低复习频率。时间只是默认建议，不是严格考核。

## 数学公式与图片

GitHub Markdown 支持常见 LaTeX 数学公式：行内使用 `$...$`，独立公式使用 `$$...$$`。只有图片才能表达的手写推导可存放于将来新增的 `assets/`，并附简短文字说明；**不要用一张图片代替全部错误分析**。

## 可验证性

仓库提供一个不需要第三方依赖的轻量检查程序：

```bash
python scripts/check_repo.py
```

它只验证 Markdown 本地链接是否存在、文件是否为 UTF-8、历史记录与目录是否能被读取；**不会自动判断数学证明是否正确，也不能证明学习者掌握了知识**。GitHub Actions 仅做同样的基础检查。
